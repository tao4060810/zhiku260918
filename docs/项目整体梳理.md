# 掌柜智库项目整体梳理

> 梳理日期：2026-09-18。本文以当前工作区代码为准，帮助理解项目、定位文件和继续开发。描述的是代码已实现的行为，不代表所有外部服务在阅读时都已启动或通过实际业务验证。

## 1. 项目定位

掌柜智库是面向产品说明书、使用方法、参数和故障问题的 RAG 知识问答应用。用户先导入 PDF 或 Markdown 文档，再通过聊天页面提问；系统从知识库及网络检索资料，交给大模型生成带引用的答案。

RAG 在本项目中的含义是：先检索相关资料，再根据资料回答。导入说明书是在建立可检索的知识库，并没有训练或微调大模型。

当前版本已实现第一阶段多用户个人私有知识库，使用单 Web 进程，已具备以下能力：

- 注册、登录、退出、修改密码；默认私有库、用户/文档/任务/历史/资产隔离。
- 普通用户上传和查询，管理员也没有跨用户读取特权。

- 批量导入 PDF、UTF-8 Markdown，显示上传和后台处理进度。
- 解析 PDF、处理文档图片、识别产品、切片、生成向量并写入知识库。
- 产品确认、多轮问题改写、普通向量检索、HyDE 检索和网络搜索。
- 结果融合、重排、流式答案、引用摘录、图片预览和答案复制。
- 会话列表、历史恢复、新建会话和删除会话。
- 接口校验、任务错误反馈、部分服务失败降级和自动化回归测试。

## 2. 整体架构

项目分为四层：

| 层次 | 代码位置 | 主要职责 |
| --- | --- | --- |
| 页面交互层 | `web/templates/`、`web/static/` | 模板继承、输入问题、上传文档、展示进度、渲染答案和管理会话 |
| Web 接口层 | `web/app.py`、`web/api/` | 参数校验、创建任务、提交后台执行、返回状态和 SSE 事件 |
| 业务工作流层 | `processor/` | 用 LangGraph 组织文档导入与检索问答节点 |
| 基础能力层 | `utils/`、`config/`、`tool/` | 模型调用、存储访问、配置、任务管理、日志等 |

页面与 API 由同一个 FastAPI 应用提供，前端通过同源地址调用接口。当前没有独立的前端构建服务，也没有把模型处理拆成独立的后台服务。

一次典型请求的调用关系为：

```text
浏览器页面
  -> Cookie 登录认证 / CSRF 校验
  -> FastAPI 路由 / 用户与知识库归属检查
  -> 创建内存任务并提交线程池
  -> 工作流适配层
  -> LangGraph 节点
  -> 模型、数据库或对象存储
  -> 更新任务结果、保存聊天历史
  -> 页面通过 SSE 或轮询展示结果
```

账号实现入口：`web/api/auth_service.py`、`auth_dependencies.py`；权限入口：`utils/knowledge_access.py`；文档/资产：`knowledge_service.py`、`asset_service.py`、`utils/knowledge_store.py`；本机管理及迁移位于 `tools/`。完整启动和接口契约以 [README](../README.md) 为准。

## 5. 文档导入流程

入口为 [import_service.py](../web/api/import_service.py) 的 `POST /upload`，后台适配入口为 [workflows.py](../web/api/workflows.py) 的 `run_import_graph()`。

### 5.1 上传和任务创建

1. 校验整批文件：每批 1 至 10 个，仅支持 `.pdf`、`.md`，单个文件最多 50 MB。
2. 校验文件名、空文件、Markdown 编码及 PDF 文件头；文件名主体最多 90 个 UTF-8 字节。
3. 保存到 `DATA_BASED_ROOT_DIR/日期/随机目录/原文件名`，默认根目录为 `output/data/`。
4. 整批校验通过后创建导入任务，并提交后台线程池；校验失败时清理本批暂存文件。
5. 原文件写入私有桶的 `knowledge/{kb_id}/documents/{document_id}/imports/{task_id}/...`，失败则结束导入，不产生公开链接。

上传返回 HTTP 202 及 `task_ids`，表示已接收任务，不代表已经入库成功。

### 5.2 导入节点

工作流定义：[import_processor/main_graph.py](../processor/import_processor/main_graph.py)。

| 顺序 | 节点 | 处理内容 |
| --- | --- | --- |
| 1 | `node_entry` | 检查输入文件，根据扩展名设置 PDF 或 Markdown 分支；Markdown 直接读取正文 |
| 2 | `node_pdf_to_md` | 仅 PDF 执行：申请上传、上传至 MinerU、轮询结果、下载并解压 Markdown 与图片 |
| 3 | `node_md_img` | 处理 Markdown 同级 `images/` 中被引用的图片，生成摘要、上传 MinIO、替换正文图片引用；没有图片目录时跳过 |
| 4 | `node_document_split` | 按标题组织切片，细分长段落，合并符合条件的短段落，保留文档和标题信息 |
| 5 | `node_item_name_recognition` | 根据标题及部分正文识别产品名，为切片补齐产品名，并将产品名称向量写入 Milvus |
| 6 | `node_bge_embedding` | 为正文切片生成稠密向量与稀疏向量 |
| 7 | `node_import_milvus` | 准备集合、删除同文档标题的旧切片、插入新切片，并回填 `chunk_id` |

PDF 与 Markdown 的区别主要在前半段；进入图片处理后使用相同的后续流程。当前上传接口不支持连同 Markdown 的本地图片目录一起上传，因此单独上传 `.md` 不会自动携带本地图片。

### 5.3 导入状态与结果

`ImportGraphState` 中的重要字段包括：

- `task_id`：对应 Web 任务。
- `import_file_path`、`file_dir`、`pdf_path`、`md_path`：文件及中间产物位置。
- `file_title`、`item_name`：文档标题与识别的产品名称。
- `md_content`、`chunks`：逐步处理的正文和切片。

Web 层最终返回的结果摘要包括 `chunk_count`、`item_name`、`file_title`，不会把完整向量数据发送给页面。

重复导入按 `(kb_id, file_title)` 识别同一文档。新产品索引和切片附带 `import_task`，只有完整成功后才更新 MongoDB 文档的 `active_task`，检索只读取已发布版本；失败保留旧版本，不影响其他用户同名文件。

## 6. 检索问答流程

入口为 [query_service.py](../web/api/query_service.py) 的 `POST /query`，后台由 `run_query_graph()` 执行 [query_processor/main_graph.py](../processor/query_processor/main_graph.py)。

### 6.1 产品确认与问题改写

`node_item_name_confirm` 读取最近聊天历史，记录当前问题，调用模型提取产品名称并改写问题，再通过产品名称向量集合匹配库内产品。

当前对齐规则以实际代码为准：

- 得分高于 `0.85` 的匹配项全部加入确认产品列表，去重后使用。
- 没有高置信度结果时，得分不低于 `0.6` 的匹配项最多取前三个作为候选。
- 存在候选但未确认时，请用户明确型号。
- 未匹配到确认项或候选项时，说明收录范围，并提示补充品牌、型号、具体问题或上传说明书。

若该节点已经产生澄清或范围说明答案，流程直接进入答案输出节点，跳过检索和重排。未提取到产品名称时会跳过产品向量匹配，再以空的对齐结果进入同一范围说明分支；当前主流程因此不会直接进入无产品过滤的全库问答。

### 6.2 三路检索

| 分支 | 输入与方法 | 输出字段 |
| --- | --- | --- |
| 普通检索 | 将改写后的问题向量化，按确认产品过滤，执行稠密与稀疏混合搜索 | `embedding_chunks` |
| HyDE 检索 | 先生成假设性文档，再向量化检索真实知识切片 | `hyde_embedding_chunks`、`hyde_doc` |
| 网络检索 | 使用改写后的问题调用智谱 `webSearchPro`，请求 3 条结果 | `web_search_docs` |

HyDE 生成的文档用于改善召回，本身不作为真实依据直接提供给最终答案。普通检索和 HyDE 检索中的稠密、稀疏评分权重当前为 `0.8 / 0.2`。

三条分支在图中并行展开，全部汇合后才进入后续节点。网络调用失败或没有有效资料时，返回空列表并记录警告，本地检索结果仍可继续使用。

### 6.3 融合与重排

`node_rrf` 只融合两路本地检索结果，以 `chunk_id` 去重，采用 `weight / (60 + rank)` 累积分数，两路权重均为 `1.0`。

`node_rerank` 再把本地 RRF 结果与网络资料合并，统一为包含 `content`、`title`、`source`、`url`、`chunk_id` 的资料结构，交给本地 Reranker 打分。

重排后最多保留 10 条；候选足够时至少保留 3 条，并根据相邻分数断崖截断。当前绝对差阈值为 `0.5`，相对差阈值为 `0.25`。这些是代码中的启发式参数，不能理解为经过业务评估验证的准确率保证。

### 6.4 答案生成与引用

`node_answer_output` 将问题、产品、历史和重排资料组装成提示词。资料与历史共享 `12000` 字符预算，先放资料，再用剩余预算放历史；这是字符预算，不是模型 token 上限。

答案生成后由 [answer_presentation.py](../utils/answer_presentation.py) 统一整理：

- 正文通过 `[cite:编号]` 对应 `sources[].source_id`，来源编号只在当前答案内有效。
- 保留实际文字引用及配图来源，资料必须确实提供给模型；过滤无效编号和重复引用。
- 模型在正文相关段落直接插入 Markdown 图片；后端核验图片属于本轮本地来源，保留合法图片位置，移除非法或重复图片。配图不依赖正文引用编号，不限制为 3 张，不额外调用选图模型。
- 读取旧历史时兼容旧引用和图片区块，不回写修改 MongoDB 中的原始记录。
- 下一轮提示词会清理历史中的旧引用编号、正文图片地址和图片区块，避免混用轮次。

答案输出节点尝试将图文 Markdown、图片白名单与来源保存到 MongoDB，再由 Web 适配层统一发送最终结果；该阶段保存失败时会附带警告，仍返回已经生成的答案。前端把正文标记显示为小号引用按钮，点击可查看摘录；流式过程中暂时隐藏引用及图片标记，收到校验后的完整答案再原位显示图片。旧版附件仍显示在底部，同一图片不重复追加。

引用校验只能确认编号和资料映射有效，不能自动证明每一句回答都被资料充分支持。

## 7. 数据保存在哪里

| 数据 | 保存位置 | 服务重启后 |
| --- | --- | --- |
| 上传文件、解析 Markdown、图片和中间产物 | 本地 `DATA_BASED_ROOT_DIR` 下 | 文件仍在，除非手动清理 |
| 原文件备份和图片对象 | MinIO 配置的桶 | 正常持久化配置下保留 |
| 正文切片和产品名向量 | Milvus 两个集合 | 正常持久化配置下保留 |
| 聊天消息和引用信息 | MongoDB 的 `chat_message` 集合 | 正常持久化配置下保留 |
| 导入任务列表、运行节点、问答任务和 SSE 事件 | Python 进程内存 | 清空，不能继续原任务 |
| 当前会话 ID | 浏览器 `localStorage` 的 `zhiku.session` | 通常保留，清理站点数据后消失 |

### 7.1 Milvus

集合名由配置决定，示例为 `kb_chunks` 和 `kb_item_names`。

- 切片集合主要字段：`chunk_id`、`content`、`title`、`parent_title`、`part`、`file_title`、`item_name`、`dense_vector`、`sparse_vector`。
- 产品集合保存产品名称及其向量，用于将问题中的产品名对齐到知识库。
- 导入时会检查并创建需要的集合与索引；更换嵌入模型或向量维度时，需要另行考虑集合和数据迁移。

### 7.2 MongoDB

一条消息主要包含：`user_id`、`kb_id`、`session_id`、`role`、`text`、`rewritten_query`、`item_names`、`image_urls`、`sources`、`ts`。

会话列表由消息聚合生成，没有独立的会话表；新建一个尚未发送消息的会话不会立即产生数据库记录。历史查询先取最近若干条，再恢复为时间正序。

删除会话会删除对应 `session_id` 的聊天消息，不会删除 Milvus 知识切片或 MinIO 文件，也不等同于清理进程内任务缓存。

### 7.3 MinIO

原文件和图片都写入新私有桶，按库、文档、任务隔离。客户端每次操作检查桶策略，不创建匿名权限；HTTPS 由 `MINIO_SECURE` 配置。页面使用 `/assets/{id}`，后端认证并核对元数据归属后代理对象，不返回 MinIO 直链。

## 8. FastAPI 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 重定向到聊天页面 |
| GET | `/chat.html`、`/import.html` | 分别渲染聊天与导入模板，两者继承公共基础模板 |
| GET | `/static/{资源路径}` | 提供脚本、样式、图片和第三方库 |
| POST | `/upload?kb_id=...` | 校验本人库，Multipart 字段 `files`，返回任务 ID |
| GET | `/status/{task_id}` | 查询导入或问答任务状态和结果 |
| GET | `/tasks` | 当前用户在本进程的导入任务 |
| POST | `/auth/register`、`/auth/login` | 注册和登录 |
| GET | `/auth/me` | 当前账号、默认库、CSRF token |
| POST | `/auth/logout`、`/auth/change-password` | 退出和改密 |
| GET | `/knowledge-bases/{kb_id}/documents` | 本人库的持久文档清单 |
| GET | `/assets/{id}` | 认证后读取本人库的文件或图片 |
| POST | `/query` | 提交 `query`、`kb_id`、可选本人已有 `session_id` 和 `is_stream` |
| GET | `/stream/{session_id}?task_id=...` | 订阅指定会话内指定任务的 SSE 事件 |
| GET | `/sessions` | 最近会话列表，默认 50 个，上限 100 |
| GET | `/history/{session_id}` | 历史消息，默认 100 条，上限 500，附带最近任务信息 |
| DELETE | `/history/{session_id}` | 删除会话；当前会话有未完成任务时返回 409 |
| GET | `/docs` | 自动生成的交互式接口文档 |

问题长度为 1 至 4000 个字符，纯空白问题会被拒绝。提交问题时的会话 ID 限制为字母、数字、下划线和连字符，最长 100 个字符；省略时自动生成。

`is_stream=true` 为默认值：先返回任务 ID，再订阅事件；`is_stream=false` 会等待后台工作流执行完毕再返回答案。两种方式都实际执行完整工作流。

常见状态码包括：401 未登录或登录失效、403 Origin/CSRF 校验失败、429 限流、400 上传内容或参数业务校验失败、413 文件超限、422 请求结构校验失败、409 任务冲突或容量已满、404 任务不存在、503 业务服务失败。

## 9. 任务状态与流式通信

任务管理位于 [task_utils.py](../utils/task_utils.py)，SSE 编码与重放位于 [sse_utils.py](../utils/sse_utils.py)。

任务状态为 `pending -> processing -> completed / failed`。页面通过 `done_list` 和 `running_list` 展示节点进度，通过 `warnings` 展示降级提醒，通过 `error` 展示失败原因。

| 事件 | 含义 |
| --- | --- |
| `progress` | 任务状态、运行节点、完成节点或警告变化 |
| `delta` | 模型答案增量，尚未经过完整引用校验 |
| `final` | 完整且已整理的答案、来源和图片 |
| `error` | 任务失败 |

事件带递增编号，重连可通过 `Last-Event-ID` 从上次位置重放。前端同时轮询任务状态，作为最终结果恢复的补充。第三方客户端应以 `final` 为最终答案，不能将原始 `delta` 直接当成已经校验的结构化结果。

当前资源限制：

- 应用只创建一个后台执行线程，导入和问答共用它；一次执行一条完整流水线，单条查询内部仍有多路检索分支。
- 未完成任务上限为 20，包含运行中和排队中的任务，并非额外允许 20 个等待任务。
- 同一会话已有未完成任务时，新问题被拒绝。
- 最多保留 500 个任务；创建新任务时清理超过一天的已结束任务。
- 每个任务最多保留最近 4096 条事件，不能保证无限期重放全部增量。
- 服务重启后不恢复任务；优雅关闭会等待已提交的工作执行完毕。

## 10. 前端组织方式

[base.html](../web/templates/base.html) 定义共享侧栏、页面导航和会话删除弹窗；[chat.html](../web/templates/chat.html) 与 [import.html](../web/templates/import.html) 通过 Jinja2 继承它，分别填充页面内容、专用样式及脚本。图片与引用弹窗只出现在聊天页。

页面脚本按职责拆分，共用 `common.js` 中的接口工具、状态和侧栏逻辑：

| 功能 | 代表函数 |
| --- | --- |
| 公共接口和反馈 | `common.js`：`api()`、`toast()` |
| 导入进度与界面锁定 | `import-status.js`：两个页面共用任务轮询；上传到入库期间锁定界面，所有任务完成或失败后恢复 |
| 导航与侧栏会话 | `common.js`：`openSession()`、`newChat()`、`deleteSession()`、`syncSidebar()` |
| 历史和任务恢复 | `chat.js`：`loadHistory()`、`connectStream()`、`pollTask()` |
| 提问、消息与引用 | `chat.js`：`sendQuestion()`、`renderAnswer()`、`openSource()` |
| 文档导入 | `import.js`：`queueFiles()`、`uploadFiles()`、`loadTasks()`、`renderTasks()` |

样式分为 `base.css`、`chat.css` 和 `import.css`，按职责保留响应式规则和中文注释。每个页面只加载自己的业务脚本和样式，导入页不会加载 Markdown 渲染库。

页面导航使用真实链接，切换时会重新加载页面。公共侧栏在聊天页通过自定义事件通知聊天脚本切换会话，在导入页则先保存会话 ID 再跳转。返回聊天页时重新读取历史及未完成任务，恢复流式订阅；离开页面只停止前端订阅和定时器，不取消后台任务。文件仍在上传时离开页面会触发浏览器确认。

Markdown 使用 marked 解析，再由 DOMPurify 清洗；流式期间先用纯文本展示，最终结果到达后再渲染 Markdown 和引用。会话删除需要确认，失败时保留会话与弹窗，避免误显示为删除成功。

### 12.2 常见问题定位

| 现象 | 优先检查 |
| --- | --- |
| 页面能打开，但历史无法加载 | MongoDB 地址、服务状态、库名和访问权限 |
| 页面能打开，但问答失败 | 检查数据库连接、凭据、集合、模型路径及后台异常 |
| 导入停留在 PDF 解析 | MinerU 凭据、外网连接和解析任务状态 |
| 导入停留在向量化或重排报错 | 本地模型目录、CPU/GPU 配置、显存及依赖兼容性 |
| 有正文但图片无法显示 | 先检查正文 Markdown 图片、最终 `image_urls` 和配图日志；没有合法图片时检查本轮资料和模型输出，否则检查资产权限、图片对象及浏览器加载 |
| 网络搜索警告但仍有答案 | 网络分支降级，当前使用本地知识资料 |
| 重启后近期任务列表为空，但持久文档仍在 | 近期任务在内存；持久文档清单从 MongoDB 加载 |
| 返回任务冲突 | 同一会话仍有任务，或全局未完成任务已达上限 |

`tool/logger.py` 当前配置的是控制台日志，没有内置日志文件轮转。Web 页面提供简短失败说明，详细异常应查看服务终端输出。

## 13. 当前边界与后续改进

以下是当前实现的边界，不应当作已经完成的功能：

1. **多用户、单 Web 进程。** 已实现登录和私有库隔离；共享只读库是第二阶段，尚未开放。任务和配额锁在当前进程，不能运行多个 worker/实例。
2. **任务不可持久恢复。** 登录会话、文档和聊天持久化，但执行中的模型任务不续跑；重启清理容量预留，未发布版本不进入检索。长导入使问答排队。
3. **没有跨存储事务。** 新向量带 `import_task`，MongoDB 的 `active_task` 决定可查询版本；全部成功才切换。失败清理本次资产与向量，极端断电/存储故障仍可能产生不可见孤立对象，后续需要垃圾回收。
4. **文档管理包含持久清单、容量和原文件下载。** 暂无文档删除、版本切换和共享成员界面。
5. **依赖保持简单。** FastAPI `Depends`、PyMongo、普通权限函数、服务端随机会话；运行依赖只新增 `pwdlib[argon2]`，测试使用 dev dependency `mongomock`。未加入 JWT、认证或权限框架。
6. **检索质量需实际业务评测。** 自动化验证范围和归属，不代表已经评测外部模型回答质量。真实服务联调记录与测试结果见 [实施记录](第一阶段实施记录.md)。
7. **旧数据默认隔离。** 迁移要求明确指定用户和库、先预览、再显式应用；无法映射的旧聊天整体保留在隔离区，不自动公开。操作见 [运维与迁移](多用户运维与迁移.md)。
8. **澄清重复历史已修复。** 产品节点只保存用户问题和改写信息，助手回答统一在输出节点保存一次。
