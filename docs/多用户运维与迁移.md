# 多用户第一阶段：运维与迁移

当前运行方式是一个 Web 实例、一个 Uvicorn worker。普通账号可注册、上传和查询自己的默认库；管理员只能管理账号，没有跨库读内容的接口。

## 配置和启动

1. `uv sync --locked`。线上可用 `uv sync --locked --no-dev`，`mongomock` 仅用于测试。
2. 对照 `.env.example` 补配置，不覆盖现有密钥。新向量集合默认 `kb_private_chunks_v1` / `kb_private_items_v1`，私有桶默认 `zhiku-private`。
3. 本地运行 `uv run uvicorn web.app:app --host 127.0.0.1 --port 8000`，访问 `/login.html` 注册账号。
4. 实际 HTTPS 部署设置 `APP_ENV=production`、`AUTH_COOKIE_SECURE=true`，`AUTH_ALLOWED_ORIGINS` 精确填写站点源，例如 `https://kb.example.com`。不使用通配 Origin。反向代理限制上传体积并关闭 SSE 缓冲；不要添加多个 worker。

用户名 3–32 位字母、数字、下划线或连字符，统一小写；密码 12–128 个字符。注册永远产生普通用户。关闭注册可设 `AUTH_REGISTRATION_ENABLED=false`。

管理员初始化：

```powershell
uv run python -m tools.manage_users create --username admin --role admin
uv run python -m tools.manage_users list
uv run python -m tools.manage_users disable --username alice
uv run python -m tools.manage_users enable --username alice
uv run python -m tools.manage_users reset-password --username alice
```

密码在终端隐藏输入，不放在命令行参数或 `.env`。禁用、启用或重置密码都会更新认证版本，使旧登录失效。普通用户可在页面改密；退出只撤销当前登录。

## 旧数据默认隔离

升级不自动迁移原有聊天、向量或对象。只有带当前账号和知识库归属的记录可被新接口读取。新向量有 `kb_id`、`document_id`、`import_task` 字段，检索同时过滤知识库和 MongoDB 发布的文档版本；旧集合不会自动参与检索。

旧程序可能给原 MinIO 桶设置过匿名策略。新代码不会擅自修改旧桶；不迁移的旧资料仍维持部署前的策略，需要管理员自行审查。下面的知识迁移命令在明确应用时关闭**整个指定旧桶**的匿名策略，并校验复制后的私有对象。若桶同时给其他应用提供公开资源，先拆分和评估，不应直接对共用桶应用。

## 知识迁移

先停 Web 服务并备份 MongoDB、两个旧 Milvus 集合、MinIO 对象和桶策略。工具需停服执行，避免在线写入与迁移同时发生。

创建一个 UTF-8 JSON 清单，明确每份文档的标题、原文件对象 key 和图片地址到对象 key 的映射。例如 `output/legacy-manifest.json`：

```json
{
  "legacy_chunks": "kb_chunks",
  "legacy_items": "kb_item_names",
  "legacy_bucket": "zhiku",
  "documents": [{
    "file_title": "说明书",
    "original_key": "说明书.pdf",
    "assets": {
      "http://127.0.0.1:9000/zhiku/images/说明书/panel.png": "images/说明书/panel.png"
    }
  }]
}
```

图片地址必须与旧切片原文一致，不能照抄示例猜测。每份文档需要存在的原文件、产品索引和完整向量；Markdown/HTML 图片引用必须全部映射，否则整份清单拒绝应用。工具不调用模型，不改写知识正文语义，只替换已映射资产地址，并为向量附加归属。

从账号管理命令取得 `USER_ID` 和 `KB_ID`，生成并保存一个 UUID 作为 `MIGRATION_ID`。以下大写字符串均需替换为真实 ID；预览和重试使用同一迁移 ID：

```powershell
# 默认仅预览，不复制对象、不关闭桶策略。
uv run python -m tools.migrate_legacy_knowledge --manifest output/legacy-manifest.json --user-id USER_ID --kb-id KB_ID --migration-id MIGRATION_ID

# 已核对预览和备份后应用；明确关闭指定旧桶匿名读取。
uv run python -m tools.migrate_legacy_knowledge --manifest output/legacy-manifest.json --user-id USER_ID --kb-id KB_ID --migration-id MIGRATION_ID --apply --close-legacy-public
```

过程保存 `migrations`、`migration_chunks`、`migration_assets`，按文档校验对象 SHA-256、切片和产品数量后发布。目标已有不同来源的同名文档、已有归属的旧记录、超额清单均拒绝覆盖。重复执行已完成文档不再插入；中断后以原清单及迁移 ID 重跑。源向量和对象保留，旧桶策略副本记录在迁移日志中，工具不重新开启匿名读取。

当前支持本项目两套既有向量字段和显式对象映射；若旧数据缺少原文件或向量，先恢复备份或重新导入，不应修改工具使未知来源默认通过。

## 聊天迁移

有本地引用的聊天先完成知识迁移。随后指定账号、库和另一个聊天迁移 UUID：

```powershell
uv run python -m tools.migrate_legacy_chats --user-id USER_ID --kb-id KB_ID --migration-id CHAT_MIGRATION_ID
uv run python -m tools.migrate_legacy_chats --user-id USER_ID --kb-id KB_ID --migration-id CHAT_MIGRATION_ID --apply
```

工具只处理没有 `user_id` 和 `kb_id` 的旧消息。无法唯一映射的本地来源、图片、混合归属会话都整段隔离并报告，不截掉引用后冒充成功。聊天分配确定的新会话 ID，消息正文保留，仅改写受控资产地址及来源标识。原消息快照和转换结果保存在 `chat_migration_plans`，中断可以恢复。

迁移计划与原文快照本身含私有内容，按数据库备份同等权限保护。

## 条件回退

先停服，依次回退聊天、知识；不带 `--apply` 仍然只预览：

```powershell
uv run python -m tools.migrate_legacy_chats --user-id USER_ID --kb-id KB_ID --migration-id CHAT_MIGRATION_ID --rollback --apply
uv run python -m tools.migrate_legacy_knowledge --manifest output/legacy-manifest.json --user-id USER_ID --kb-id KB_ID --migration-id MIGRATION_ID --rollback --apply
```

聊天新增、修改、删除或知识文档已更新时，工具拒绝覆盖新变化。知识回退要求目标库没有聊天，避免留下失效引用。回退删除本次迁移的新副本，旧源仍保留，旧桶匿名策略保持关闭。恢复旧代码只能在隔离维护环境进行，旧代码不能对外提供多用户访问。

## 重启与清理

优雅退出会等待已接收任务结束；异常退出后任务进度不恢复。启动时释放未完成文档预留，之前已成功的文档版本仍可检索。后台正常失败会清理本次产物；突然断电、数据库或对象存储持续故障可能留下未发布向量/资产，不进入检索，但占用存储。当前没有自动垃圾回收、文档删除或多实例协调工具，维护时先备份再按文档活动版本核对，不按文件名跨库删除。
