| 项目 | 内容 |
| --- | --- |

| 日期 | 2026-09-18 |
| 代码基线 | `09e0347`：页面模板拆分及公共导入进度管理 |
| 目标 | 增加账号认证、个人文件上传、私有知识库及按用户授权的查询，并隔离聊天、任务和文件 |

| 第二阶段 | 在第一阶段之上增加指定用户只读授权、撤销和选库交互 |

## 1. 范围与待确认事项

第一阶段交付用户名密码注册、登录、退出、修改密码、管理员初始化、普通用户文件上传和个人私有知识库，以及问答、历史、任务、SSE、向量检索和文件访问的权限隔离。每个用户只操作自己的一个知识库，不提供分享和成员管理入口。

第二阶段再增加指定用户只读授权、撤销和切换知识库。第一阶段可以独立验收和交付，不以完成共享授权为前提。两阶段均保留现有检索算法、引用展示、单进程部署和后台串行执行方式。

已确认采用简单、常见、可直接阅读的代码实现，并按上述两个阶段推进。下文没有注明阶段的安全、归属和存储规则均为第一阶段要求；涉及 `reader`、成员表、授予/撤销、跨库选择的规则仅在第二阶段实现。保留 `kb_id` 等稳定数据标识，不提前引入通用权限引擎。

| 事项 | 本文默认值 | 改变后的影响 |
| --- | --- | --- |
| 知识库归属 | 每个账号默认一个私有知识库；数据范围以 `kb_id` 标识 | 后续可扩展一人多个库或团队库，第一版不提供多库创建和团队组织 |
| 注册方式 | 开放用户名密码注册，可通过配置关闭 | 邀请注册、邮箱验证需要另外设计凭证和流程 |
| 上传权限 | 普通用户和管理员都可上传到自己拥有的库 | 受邀只读用户不能上传、覆盖文档或再次授权 |
| 指定用户查询 | 第二阶段：拥有者按准确用户名授予或撤销 `reader`；无公开链接 | 第一阶段不开放成员接口，也不因数据库存在手工成员记录而允许跨用户查询 |
| 旧聊天记录 | 默认隐藏，支持显式迁移给一个指定账号 | 不允许自动归给首个注册用户，也不默认向全部用户公开 |
| 文件及图片 | 私有 MinIO 桶，应用验证权限后代理读取 | 原有匿名 URL 不能保留为受保护文件的旁路访问方式 |

本阶段不包含邮箱/短信验证、忘记密码邮件、第三方登录、完整用户管理后台、团队组织、协作写入、完整文档删除与版本管理、分布式队列或多进程部署。管理命令可以创建管理员、禁用账号和重置密码，补足基本维护能力。

**交付定义：支持多个账号使用系统，数据权限可靠隔离；不承诺同时运行多条模型流水线。**

### 1.1 技术选型与复用方式

| 需求 | 实现方式 | 代码约束 |
| --- | --- | --- |
| 请求和字段校验 | 现有 FastAPI、Pydantic | 普通路由函数和请求模型 |
| 获取当前用户 | FastAPI 自带 `Depends(get_current_user)` | 从 Cookie 读取随机凭证，查 MongoDB 登录记录及用户 |
| 账号和登录存储 | 现有 PyMongo | 直接使用 `find_one`、`insert_one`、`update_one`、唯一索引和 TTL 索引 |
| 密码保护 | 新增 `pwdlib[argon2]` | 只复用密码哈希、验证及必要的哈希升级；不自行设计密码算法 |
| 随机凭证和比较 | Python 标准库 `secrets`、`hashlib`、`hmac` | 安全随机数、凭证摘要、常量时间比较 |
| Cookie | FastAPI/Starlette 已有 `set_cookie`、`delete_cookie` | 凭证为不透明随机值，状态保存在 MongoDB |
| 知识库权限 | 普通 Python 函数和数据库归属条件 | 第一阶段比较 `owner_user_id`；第二阶段仅补充 reader 成员查询 |

本次不引入 FastAPI Users、Casbin、Keycloak、Beanie、Redis、额外 ORM 或通用认证中间件。不新增 JWT 依赖、访问令牌/刷新令牌双令牌机制、策略表达式语言和角色继承体系。现有框架内部依赖不受此条限制。

参考 FastAPI 官方教程和官方全栈模板的“路由 -> 当前用户依赖 -> 明确归属检查”组织方式，只改造需要的功能；模板的 PostgreSQL/SQLModel 查询替换为现有 PyMongo，Bearer JWT 登录替换为本文的服务端 Cookie 会话。模板允许超级管理员跨用户访问的逻辑不采用。

### 1.2 最小代码职责

统一入口使用清楚的函数名即可：

```python
get_current_user(request)  # 校验登录记录、过期和用户状态
require_kb_permission(user_id, kb_id, action="read")
require_kb_permission(user_id, kb_id, action="upload")
```

`require_kb_permission` 是权限入口的契约示意，不是现成可执行代码。实现接收服务端确认的用户 ID，读取知识库，第一阶段要求拥有者相符；成功返回知识库记录，失败抛出统一业务异常。只允许已声明动作，未知动作默认拒绝。第二阶段才增加 `manage_members` 以及 `read` 对 reader 的判定。

API 层用 `Depends` 获取身份并将异常转换为 HTTP 状态；后台任务调用同一个普通权限函数。数据库查询和 Milvus 请求仍显式附带范围，不能仅靠入口检查后做无范围查询。避免另外设计通用 Repository、权限装饰器链或复杂抽象基类；相关小函数可放在同一职责模块。

## 2. 当前实现与改造原因

| 当前实现 | 需要改造的行为 |
| --- | --- |
| `web/templates/` 已按公共布局、聊天、导入拆分 | 增加独立认证布局和账号入口，避免登录页加载聊天及任务轮询 |
| `chat_message` 只有 `session_id`，会话列表直接聚合所有消息 | 增加 `user_id`，所有读取、聚合、更新和删除均限定归属 |
| 会话 ID 由浏览器生成，无独立归属记录 | 增加 `chat_sessions`，由服务端创建会话并固定拥有者 |
| 内存任务没有所属用户 | 创建时写入不可变 `user_id`，状态、历史恢复和事件重放均检查归属 |
| `/stream` 只检查任务所属会话 | 同时验证登录状态、用户、会话和任务类型 |
| `/tasks` 返回全局导入详情，两个页面据此锁定 | 每人仅看自己的导入任务并据此锁定；不暴露其他库的活动 |
| 产品名称匹配和正文检索缺少知识库过滤 | 产品匹配、普通检索、HyDE 都强制限定已授权的 `kb_id` |
| 切片按文档标题删除，产品名按名称删除 | 文档归属使用 `kb_id + document_id`，同名文档及产品不跨库覆盖 |
| 图片使用按标题生成的对象路径和匿名 URL | 对象按知识库及文档分目录，引用改为需认证的资产接口 |
| 产品确认和答案输出都可能保存澄清答案 | 在改造历史写入时统一由答案输出节点保存一次助手消息 |

现有验证基线为 34 项 Python 测试和 4 个前端测试脚本通过；外部模型及数据库使用替身，真实业务链路需在实现后另行验证。

## 3. 用户体验和角色权限

### 3.1 基本流程

1. 未登录访问聊天页，跳转登录页；登录后进入聊天页。只接受站内白名单目标作为 `next`，不允许任意外部跳转。
2. 注册填写用户名、密码、确认密码；成功后进入登录页，不自动建立登录会话。
3. 登录成功显示用户名、“我的知识库”和文档管理入口；普通用户可以上传、查看自己的导入进度和文档清单。
4. 第一阶段自动使用本人的默认库，不显示选库器；新聊天首次提问时由服务端分配聊天 ID 并固定其 `kb_id`。第二阶段才可选择被授权库，更换知识库必须新建聊天，防止跨库混入历史。
5. 退出时撤销当前登录凭证、断开 SSE、停止轮询、清除页面私有内容并跳转登录页。
6. 修改密码要求当前密码，成功后撤销该账号全部登录凭证，所有设备重新登录。
7. 登录过期时统一提示“登录已失效，请重新登录”；不得让导入锁定弹窗遮挡登录跳转。
8. 第二阶段：拥有者可在自己知识库的“访问权限”中添加准确用户名为只读成员；对方随后可以选择该库进行查询，但看不到拥有者或其他人的聊天、任务和上传原文件。

### 3.2 权限矩阵

本表描述两个阶段的最终规则；第一阶段所有“获授查询权限”“reader”“授予/撤销”能力均不启用，所有业务内容仅本人可访问。管理员仍不享有内容访问旁路。

| 能力 | 未登录 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 注册、登录 | 允许，受开关及限流约束 | 可退出后切换账号 | 可退出后切换账号 |
| 发起问答 | 禁止 | 仅自己拥有或获授查询权限的库 | 与普通用户相同，不自动跨库 |
| 查询、删除聊天记录 | 禁止 | 仅自己的 | 仅自己的 |
| 查询问答任务、订阅 SSE | 禁止 | 仅自己的 | 仅自己的 |
| 上传文档 | 禁止 | 自己拥有的库 | 自己拥有的库 |
| 查看导入任务详情 | 禁止 | 仅自己的 | 仅自己的 |
| 文档清单、原文件下载 | 禁止 | 自己拥有的库 | 自己拥有的库 |
| 查询返回的引用和图片 | 禁止 | 当前仍有查询权限的库 | 与普通用户相同 |
| 授予、撤销知识库查询权限 | 禁止 | 仅自己拥有的库 | 仅自己拥有的库 |
| 查看知识库是否正在更新 | 禁止 | 仅可访问库的最小状态 | 与普通用户相同 |
| 更改角色或禁用其他用户 | 禁止 | 禁止 | 本阶段网页端不提供，使用管理命令 |

应用内管理员身份不授予他人知识库、文件、图片、任务或聊天的访问权限。任务 ID、聊天 ID 和 UUID 的不可猜测性不替代归属检查。拥有者查询权限隐含有效，不通过公开接口转让归属；只读成员仅能查询并查看返回的引用和图片。

### 3.3 授权撤销（第二阶段）

撤销读者后，其后续问题、排队任务、任务结果、事件重放、历史正文及图片访问都重新检查知识库权限。该用户的会话列表可保留不含原始标题的“知识库访问权限已失效”占位，可删除自己的记录，但不可再打开或把这些记录送入模型。同一账号重新获授后可以恢复原聊天。

已发给用户的内容、截图或下载无法收回。撤销只保证后续服务端读取与推送停止；执行中的云模型请求可能无法取消，结果应丢弃并标记任务为 `KB_ACCESS_REVOKED`。活动 SSE 最长 5 秒内复核权限并关闭；后台在开始执行、检索前、构造提示词前及保存/返回答案前分别复核。

## 4. 账号、密码与登录状态

### 4.1 用户名和密码

- 用户名为 3–32 位 ASCII 字母、数字、下划线或连字符；先去掉首尾空白，再转小写作为唯一键。大小写不同视为同名。
- 密码为 12–128 个字符，允许 Unicode 和空格，不裁剪、不静默截断；后端和前端采用一致的长度定义并覆盖 Unicode 测试。不要求机械组合大小写和符号。
- 使用 `pwdlib[argon2]` 保存 Argon2id 哈希及验证密码；参数使用库的推荐配置并在部署机器上验证耗时。
- 密码、Cookie 原始凭证、CSRF token 不写日志、不回传到用户资料中。注册请求不接受角色、用户 ID 等额外字段。
- 密码错误、用户名不存在、账号禁用统一返回“用户名或密码错误”；不存在账号时也执行预置哈希验证，减小明显的耗时差异。
- 重名由数据库唯一索引最终裁决，注册并发冲突返回 409。数据库故障返回 503，不解释为密码错误。

### 4.2 服务端会话

登录凭证与聊天会话分别称为 `auth_session` 和 `chat_session`，避免混用。

- 登录时生成至少 32 字节安全随机凭证，浏览器通过 `zhiku_auth` Cookie 携带；MongoDB 仅保存凭证的 SHA-256 哈希。
- Cookie 设置 `HttpOnly`、`SameSite=Lax`、`Path=/`，不设置 `Domain`。HTTPS 部署必须启用 `Secure`；本机 HTTP 开发可显式关闭。
- 默认绝对有效期 24 小时，空闲有效期 2 小时；均由服务端校验。活跃请求可以更新最近使用时间，但不能延长绝对有效期。
- MongoDB TTL 仅负责清理，认证每次显式判断是否过期、被撤销，以及用户是否启用，不能等 TTL 删除才使登录失效。
- 每次登录创建新凭证；已有有效凭证在切换账号时撤销，不复用旧凭证。其他设备的独立登录可保留。
- 密码或账号状态改变时增加用户的 `auth_version`；登录记录保存创建时版本，认证发现不一致即拒绝，保证旧会话全部失效。
- MongoDB 不可用时认证返回 503，禁止回退为匿名或默认管理员。
- 认证相关响应、聊天历史、任务结果和 SSE 设置禁止缓存；登录凭证不放在 URL 或浏览器 Web Storage。

### 4.3 CSRF 和请求限制

- 对所有有副作用的浏览器请求验证 `Origin` 精确匹配配置的站点源，缺失、`null` 或不匹配均返回 403。不配置任意来源的凭证 CORS。
- 登录、注册只接受 JSON 请求，校验内容类型和 Origin，防止跨站建立或切换登录状态。
- 已登录的 POST、DELETE 等操作额外要求 `X-CSRF-Token`，与当前服务端登录记录中的随机 token 常量时间比较。
- 登录成功及 `/auth/me` 返回 CSRF token，前端只保存在内存；上传的 XMLHttpRequest 同样携带该请求头。
- SSE 使用同源 Cookie，不把认证 token 放到查询参数中；GET 必须无业务写入副作用。
- 登录默认限制每 IP 每分钟 20 次、每规范化用户名每 15 分钟 10 次；注册每 IP 每小时 5 次；修改密码每用户每 15 分钟 5 次。超限返回 429 和 `Retry-After`。
- 第一版限流器可在单进程内存中实现，必须有容量上限、过期清理和线程安全；重启会清空计数。代理 IP 只从明确配置的可信代理获取。

## 5. 数据结构与索引

用户、知识库、文档、资产和聊天 ID 在业务层统一使用服务端生成的 UUID 字符串；消息 `_id` 继续使用现有 ObjectId，避免类型混用。`user_id` 表示操作者或消息拥有者，`kb_id` 表示数据授权范围，不能用上传者 ID 替代知识库授权。

| 集合 | 主要字段 | 索引 |
| --- | --- | --- |
| `users` | `_id`、`username`、`password_hash`、`role=user/admin`、`is_active`、`auth_version`、`created_at`、`updated_at` | `username` 唯一 |
| `auth_sessions` | `_id`、`token_hash`、`user_id`、`auth_version`、`csrf_token`、`created_at`、`last_seen_at`、`expires_at`、`revoked_at` | `token_hash` 唯一；`user_id`；`expires_at` TTL |
| `knowledge_bases` | `_id`、`owner_user_id`、`name`、`status`、`created_at`；第二阶段增加 `acl_version` | `owner_user_id` 唯一，保证每人一个默认库 |
| `knowledge_members`（第二阶段新增） | `kb_id`、`user_id`、`permission=reader`、`created_at` | `(kb_id, user_id)` 唯一；`user_id` |
| `documents` | `_id`、`kb_id`、`uploaded_by`、`filename`、`file_title`、`status`、`size_bytes`、`created_at`、`updated_at` | `(kb_id, file_title)` 唯一；`(kb_id, created_at)` |
| `assets` | `_id`、`kb_id`、`document_id`、`kind=original/image`、`bucket`、`object_key`、`content_type`、`size_bytes` | `object_key` 唯一；`(kb_id, document_id)` |
| `chat_sessions` | `_id`（聊天 ID）、`user_id`、`kb_id`、`created_at` | `_id` 唯一；`(user_id, kb_id)` |
| `chat_message` | 原有字段增加必填 `user_id`、`kb_id`，本地引用包含 `document_id` | `(user_id, session_id, ts降序, _id降序)` |

新增日期字段统一为 UTC BSON datetime，TTL 字段必须使用日期类型；本次保留旧消息 `ts` 数字格式，避免无关的历史格式迁移。

`chat_sessions` 负责用户归属和固定知识库，列表标题、消息数量与排序仍从当前用户消息聚合，未发送消息的空会话不必出现在侧栏。第一阶段每次读取确认用户及库的拥有者；第二阶段扩展为当前有效查询权限，并对失权聊天隐藏原问题生成的标题。

历史存储函数强制要求 `user_id`，包括 `save_chat_message`、`get_recent_messages`、`list_sessions`、`clear_history` 和 `update_message_item_names`。读取和写入正文还要求已验证的 `kb_id`；更新消息必须同时匹配消息 ID、用户 ID、聊天 ID 和知识库 ID。删除仅需消息用户归属，以允许删除失权聊天；禁止缺少范围时回退为全局查询。

注册和管理命令都须确保用户的默认库存在。用户创建与默认库初始化要幂等：若中途失败，重试或下次登录修复同一默认库，未完成初始化时不允许上传，不能重复创建或把半成品注册报告为成功。

### 5.1 Milvus 的强制范围

- 正文切片集合和产品名称集合均新增必填 `kb_id`、`document_id`；正文结果还返回这两个字段用于复核和引用，不只保存上传者。
- 每次查询只使用一个已授权库，第一阶段固定本人的库。产品名匹配先过滤 `kb_id == 授权库`；普通与 HyDE 的每条稠密、稀疏请求都使用 `kb_id == 授权库 AND 产品条件`。无产品条件时仍保留知识库条件。
- 空范围、无权限或缺少 `kb_id` 时直接拒绝；不得先全库召回再仅在前端或重排后过滤。
- 统一由服务端范围构造函数生成过滤表达式。ID 校验、字符串转义与授权独立执行，客户端不能提交任意过滤语句。
- 产品名写入按 `(kb_id, document_id)` 管理，每份文档可保留自己的产品名条目；同名产品在不同文档或不同库不能互相删除，查询侧在授权范围内去重。
- 同名文档仅在同一个库内复用 `document_id` 并替换切片，删除条件至少包含 `kb_id AND document_id`；不同用户上传同名文件不会相互覆盖。当前先删后插在同一库内仍有失败风险，本期不宣称事务性替换。
- 缺少新字段的旧集合不得直接承载新私有数据。准备带显式 schema 的新集合，迁移核验后切换配置；字段和索引能力以实际部署的 Milvus 版本验证为准。
- RRF、重排、引用和最终提示词只接收当前库的本地结果；缓存如有引入，键必须包含库和有效授权范围，不能按问题或产品名全局复用。

### 5.2 文件与图片保护

- 新文档使用私有 MinIO 桶。对象路径示例为 `knowledge/{kb_id}/documents/{document_id}/imports/{task_id}/...`，图片和原文件均隔离；本地暂存及中间产物同样使用库、文档和任务目录，不能仅按标题组织。
- 删除 `get_minio_client()` 自动设置图片匿名读取策略的行为。应用公开静态目录不能映射上传目录，MinIO 管理凭据不交给浏览器。
- 用 `assets` 映射随机资产 ID 与实际对象；浏览器访问同源 `/assets/{asset_id}`，服务端查元数据并验证权限后代理字节流。客户端不能指定桶、对象路径或任意外部 URL。
- 第一阶段所有资产仅知识库拥有者可读。第二阶段 `kind=image` 才允许有效只读成员查看，`kind=original` 仍仅允许拥有者下载。返回 `Cache-Control: private, no-store`；原文件强制附件下载，图片限定受支持 MIME 类型并设置 `nosniff`。
- Markdown 切片、回答和历史引用使用上述同源资产路径，不输出 MinIO 直链或长效签名 URL。同步调整后端图片提取白名单与前端 URL 校验：只接受规范化的本站 `/assets/{合法ID}` 路径，不允许协议相对地址或任意路径。
- 模型选择图片必须引用传入的本库资产；引用校验不能只检查文本 URL 相同，还要确认资产所属文档和库。视觉模型所需图片由后台读取并使用现有受控模型调用传输，不为模型访问而开放公共桶。
- 旧匿名图片迁入私有桶、重写切片与历史链接后，需关闭原对象的匿名访问并确认旧 URL 已失效。无法确认归属的图片和记录进入隔离清单，不能继续以旧公开链接兜底。历史迁移前保留备份及映射，不任意修改答案正文。

## 6. 接口契约

### 6.1 新增接口

除标注第二阶段的成员接口外，其余均在第一阶段实现。第一阶段只返回本人的默认知识库，权限值只有 `owner`；第二阶段扩展为拥有及获授权限的库。成员接口在第一阶段不注册，访问返回 404，不能仅在前端隐藏。

| 方法与路径 | 请求或用途 | 成功结果 |
| --- | --- | --- |
| `GET /login.html` | 登录页面 | HTML |
| `GET /register.html` | 注册页面；注册关闭时展示关闭说明 | HTML |
| `POST /auth/register` | `{username, password, password_confirm}` | 201，返回 `{user: {id, username, role}}`，不返回凭证 |
| `POST /auth/login` | `{username, password}` | 200，设置 Cookie，返回 `{user, csrf_token}` |
| `GET /auth/me` | 当前登录用户 | 200，返回 `{user, csrf_token}`；用户结构同上 |
| `POST /auth/logout` | 撤销当前登录并清 Cookie | 204；无有效登录时仍可在 Origin 合法后清 Cookie，保持幂等 |
| `POST /auth/change-password` | `{current_password, new_password, password_confirm}` | 204，增加 `auth_version`，清 Cookie |
| `GET /knowledge-bases` | 当前用户拥有及获授查询权限的库 | 200，`{items: [{id, name, permission: owner/reader}]}`；不含无权库 |
| `GET /knowledge-bases/{kb_id}/members`（第二阶段） | 仅拥有者查看自己授予的读者 | 200，返回必要的用户 ID、用户名、权限，不提供全站用户列表 |
| `PUT /knowledge-bases/{kb_id}/members`（第二阶段） | 拥有者提交 `{username, permission: reader}` | 200，幂等授予指定已存在账号，增加 `acl_version` |
| `DELETE /knowledge-bases/{kb_id}/members/{user_id}`（第二阶段） | 拥有者撤销读者 | 204，幂等撤销并增加 `acl_version`；不能删除拥有者身份 |
| `GET /knowledge-bases/{kb_id}/documents` | 拥有者查看持久文档清单 | 200，分页返回自己的库内文档，不依赖进程内任务记录 |
| `GET /knowledge-bases/{kb_id}/status` | 拥有者或读者查看该库导入状态 | 200，`{importing: boolean}`，不含其他库活动或导入任务详情 |
| `GET /assets/{asset_id}` | 登录后按资产类型验证知识库权限 | 200，代理原文件或图片；无权/不存在均 404，不重定向到公开对象 URL |

有有效登录状态的退出请求仍要求正确 CSRF token。认证及授权请求模型禁止未声明字段；知识库成员接口先验证拥有者再查询目标用户名。不存在目标账号返回 404，不能用该接口批量枚举用户；每拥有者每分钟最多 10 次成员变更或用户名尝试，超限 429。拥有者不能给自己设置 reader，返回 409。

### 6.2 现有接口修改

| 接口 | 新行为 |
| --- | --- |
| `GET /chat.html` | 需要登录，匿名跳转登录页 |
| `GET /import.html` | 所有登录用户可访问，匿名跳转登录页 |
| `POST /query` | `{query, kb_id, session_id?, is_stream?}`；登录、CSRF、库查询权限；新建聊天固定 `kb_id`，已有聊天必须属于当前用户且库一致，库不一致返回 409 |
| `GET /sessions` | 只聚合当前用户消息，返回所属 `kb_id`；失权会话仅返回脱敏占位，结构保持 `items` |
| `GET /history/{session_id}` | 同时校验聊天拥有者与库查询权限；消息和 `active_task` 限定当前用户和库 |
| `DELETE /history/{session_id}` | 登录、CSRF、归属检查；有未结束任务返回 409；成功删除消息及归属记录 |
| `GET /status/{task_id}` | 仅任务创建者且仍有对应知识库权限时可读取；库 reader 不能查看其他人的导入任务 |
| `GET /stream/{session_id}` | 校验用户、库权限、聊天与任务归属且任务为问答；重连和重放同样检查 |
| `POST /upload?kb_id=...` | 所有登录用户可调用，须为目标库拥有者并通过 CSRF；在业务持久化前完成授权；元数据中的上传者、库和文档 ID 来自后端 |
| `GET /tasks?kb_id=...` | 返回本人的导入任务，可选按自己拥有的库过滤；不返回其他上传者或失权库的详情 |

静态资源可以公开访问，不包含账号或业务数据；生产部署的 `/docs`、`/redoc`、`/openapi.json` 默认关闭，开发模式可开启。

错误约定：未登录或凭证失效 401；CSRF 不满足或可见库的 reader 试图上传/授权为 403；无权知识库、他人资源与不存在资源统一 404；用户名冲突、运行中会话、库不一致或容量限制 409；字段校验 422；限流 429；数据库故障 503。保留上传的 400/413 等现有错误。权限撤销的历史正文接口返回 404，前端依据会话列表的脱敏状态显示失权提示。

鉴权依赖和归属检查不放入现有宽泛的 `except Exception` 中，避免把 401/403/404 转成 503。权限拒绝不得创建任务、调用模型或写入聊天数据。

## 7. 工作流、并发和 SSE

### 7.1 用户身份传递

调用链固定为：`认证依赖 -> 知识库授权 -> 接口 -> 任务 -> 工作流状态 -> 检索/存储 -> 输出前复核`。

`QueryGraphState` 增加必填 `user_id`、`kb_id`；`ImportGraphState` 增加 `user_id`、`kb_id`、`document_id`。用户来自登录态，知识库 ID 必须经服务端授权验证，文档 ID 由后端分配或在本库内解析。任务记录固定这些字段，不能从全局当前账号或最新选库状态重取。

角色判断与库授权分开，库授权统一使用 `require_kb_permission`，无需同时实现多套等价检查函数。第一阶段 read、upload 均要求本人拥有；第二阶段增加 read 的 reader 分支和 manage_members 动作。reader 查询时仍以查询者为消息拥有者，绝不能把回答保存进知识库拥有者的聊天。当前库无资料时不能回退到全站产品名或全站文档；范围提示也只描述当前库。

联网搜索保持现有补充检索行为，但只能使用当前已授权会话的问题，不能拼入其他库名称或片段；网络结果继续标为网络来源，不视为私人库的文档。已有 LLM、PDF 解析和视觉服务仍属于实际处理链，私有库指应用内访问隔离，不表示全部处理均在本机。

产品确认节点保存用户消息并更新其关联信息；所有助手答案（含澄清、未收录提示）只由答案输出节点保存一次。现有流式与非流式答案、引用保存一致性必须保持。

### 7.2 任务容量和删除竞态

- 保留单个 Uvicorn worker、单个后台执行线程，以及全局 20 个未完成任务上限。
- 每用户最多一个未完成问答任务，跨聊天窗口生效；最多 10 个未完成导入任务、每批最多 10 个文件、单文件最多 50 MB。全部用户共享全局任务容量，角色不豁免配额。
- 默认每人最多 100 份文档和 1 GiB 原文件，限额可配置；全量输出文件、图片及向量另受部署磁盘和集合容量约束，不把原文件限额误称为全部存储配额。按文档大小差额及排队预留原子计费，失败释放预留；并发上传不能绕过计数，同名替换不能重复占文档名额。
- 同会话冲突检查以用户和聊天归属为基础；任务必须先通过归属检查再创建。
- 批量上传的容量检查和全部任务预留应作为一个原子操作：容量不足整批拒绝，不留下部分可执行任务。
- 删除聊天与提交问答共用会话级协调机制：删除期间拒绝新提问；任务预留完成后拒绝删除。检查、标记和解除标记必须覆盖异常路径，不能采用分离的“先检查后操作”。
- 线程池提交失败时把预留任务标为失败，释放活动配额；新建空会话可保留但不显示在侧栏。
- 退出和密码修改不取消已接受的后台任务，结果仍保存给原用户；重新登录原账号且仍有库权限后可以恢复。库授权撤销或账号禁用使尚未执行的任务失败，运行中的任务不再发布结果；清理新建的未完成产物，已有有效文档不跨库删除。

### 7.3 长连接失效

- SSE 建连及每次重连检查有效登录、资源归属和知识库查询权限；查询缓存结果与重放旧事件不能绕过当前授权。
- 活跃连接至少每 5 秒重新校验一次登录是否被撤销、过期、禁用或版本变化；发现失效后不再推送业务事件，发送 `error`（`code: AUTH_EXPIRED`）并关闭。
- 第二阶段同时复核库成员权限，撤销时发送 `error`（`code: KB_ACCESS_REVOKED`）并关闭；不能继续显示私有引用、图片和任务结果。已送达内容无法技术性收回。
- 数据库故障时不继续发送未经重新验证的内容，发送 `error`（`code: AUTH_UNAVAILABLE`）并关闭；界面提示服务暂不可用。
- 恢复每 15 秒一个 SSE 注释心跳，减少长时间模型计算期间连接被中间代理断开的概率；保留 `Last-Event-ID` 重放和最终结果轮询。
- 非流式问答等待完成后，在发送答案前再次验证登录和库权限，避免长时间等待后向已失权用户返回答案。
- 现有任务终态和 `final` 事件应以一致快照发布，防止轮询/SSE 先看到“完成”却拿到不完整的最终元数据。

## 8. 页面和导入锁定调整

第一阶段页面仅显示“我的知识库”、本人文档和账号菜单；下列选库、只读提示、成员授权和失权占位交互在第二阶段实现。保持现有原生 JS 和 Jinja2，不引入新前端框架。

- 新增不依赖 `common.js` 的认证页面布局，只加载认证样式与脚本；支持提交中状态、字段错误和服务不可用提示。
- 主布局增加用户名、退出、修改密码、知识库选择和文档管理入口，普通用户完整可用；查询被授权的库时显示“只读”，隐藏上传及成员管理操作，后端仍执行权限检查。
- 主页面先确认 `/auth/me`，再获取 `/knowledge-bases`、历史和自己的任务。文档页展示本人库的持久文档清单、导入任务和配额，不把授权只读等同于允许下载原文件。
- 浏览器只保存当前聊天 ID，键改为 `zhiku.session.<user_id>`；不沿用旧的全局 `zhiku.session`，遇到不属于本账号的旧 ID 时清除并新建。
- 所有异步请求、SSE 回调带账号/页面代次检查。退出或切换账号后，旧响应不能写回新账号页面。
- Cookie 在同源标签页间共享；使用 BroadcastChannel 或不含凭证的 storage 事件通知其他标签页重新验证账号。窗口重新获得焦点及往返缓存恢复时也验证，清除旧账号内容。
- `common.js` 统一处理 401 和 CSRF 请求头；`import.js` 的 XMLHttpRequest 单独覆盖同样行为，不能只改 fetch。
- 上传前明确显示目标知识库；第一阶段文案为“仅本人可查询”，第二阶段调整为“仅本人及已授权读者可查询”。两个阶段上传目标均仅为本人拥有的库。一次批次内同标题文件直接拒绝，避免同批相互替换。
- 所有上传者保留当前账号的进度弹窗，仅以自己的任务判断锁定；可点击“终止上传”取消本人仍在处理的任务，已完成文件不回退，任务查询 503 可维持锁定重试，401 必须转登录，失权时清理锁定并显示无权限。
- 终止不退出账号。传输阶段使用按账号隔离的上传批次 ID 记录取消，防止中断连接后后台继续接收；解析阶段先进入 `canceling`，当前外部调用返回后停止后续节点，完成清理后进入 `canceled`。取消和文档版本发布共用锁，取消中的任务仍计入活动任务上限。
- 当前可读库正在导入时，通过 `/knowledge-bases/{kb_id}/status` 显示更新提示；其他库的任务只影响全局排队速度，不显示其库名、文件名或上传者。任何用户都不因他人的导入弹窗而锁死。
- 知识库“访问权限”只向拥有者显示；按准确用户名添加 reader，展示当前授权列表并可撤销。读者只能选择库查询，不能再次分享。撤销提示说明对方已看到的内容无法收回。
- 当前知识库失权时停止提问、SSE 和结果轮询，清理当前页面的受保护内容；提供返回自己知识库及删除本人失权会话入口。旧图片 URL 或历史中的原始对象链接不能作为权限失败兜底。

## 10. 初始化、迁移与回退

1. 备份 MongoDB、Milvus 数据及 MinIO 对象/策略；暂停新请求并等待任务结束，避免迁移期间旧程序写入无归属数据。
2. 创建新集合和索引，使用管理命令显式创建管理员及其默认私有库。公开注册永远创建 `user`，不使用“第一个注册者自动成为管理员”。
3. 无归属的旧消息和文档默认隔离，不向新用户公开。旧向量不进入新私有库查询，旧桶不得继续匿名暴露准备作为私有数据使用的对象。
4. 如要保留旧聊天给指定账号，迁移命令必须提供目标用户 ID，默认只预览消息数、聊天数和冲突；显式应用后才写入。
5. 旧知识库迁移必须指定目标 `kb_id` 和明确拥有者，建立文档/资产映射，向新 Milvus 集合写入带范围字段的产品及切片。按对象校验复制和私有读取后，替换受控资产引用并禁用旧对象匿名访问。新账号不得默认查询全部旧数据。
6. 迁移只处理缺少归属的记录，不覆盖已有归属；聊天只能绑定一个明确的知识库。旧聊天引用跨多个库或无法判定来源时隔离并报告，不自动扩大权限，也不丢掉无法映射的链接后假装迁移成功。
7. 保存迁移 ID、原记录/对象 ID、原字段状态及新资产映射；支持重复运行、中断后恢复和条件回退。正文语义与引用关系不变，仅按映射更新需要替换的资产地址。新集合切换前核对文档、切片、产品、资产计数及权限。
8. 第一阶段通过私有库隔离验证后即可开放入口，不等待只读授权。第二阶段发布前另行验证授权和撤销。更新文档中的测试数量和完整测试命令。
9. 回退旧代码前关闭对外访问并备份。旧代码既不限定用户也不限定知识库，不能直接恢复对外服务；在隔离维护环境回退，且不能为了旧页面恢复显示而重新开放私有对象的匿名读取。

## 11. 分阶段实施与交付

### 11.1 第一阶段：最基本的个人私有知识库

按以下顺序实现，完成后形成可独立使用的版本：

1. 复用官方教程的密码验证思路，用 PyMongo 完成用户和登录记录存取，建立 Cookie 登录态以及 `get_current_user` 依赖。
2. 创建唯一默认知识库，用 `require_kb_permission` 做直接拥有者判断；补齐注册、登录、退出、改密和必要防护。
3. 普通用户可上传到本人库，产品索引、切片、同名替换、原文件和图片全部限定 `kb_id`。
4. 聊天、任务、SSE、历史和导入进度按用户隔离，认证页面和本人文档页形成完整操作流程。
5. 处理旧数据隔离及按需迁移，关闭私有资产旧匿名入口，完成第一阶段自动化测试和双账号实际验证。

交付时没有成员表使用、分享路由、reader 权限或选库器。其他用户即使手工提交他人的 `kb_id`，也不能访问。文件保护、CSRF、模型上下文隔离和后端归属检查不能以“简化第一版”为由省略。

### 11.2 第二阶段：指定用户只读授权

在第一阶段通过验收后，再逐项增加：

1. `knowledge_members`、`acl_version` 和授予/撤销接口。
2. 在现有权限函数的 read 动作中增加 reader 分支，upload 始终要求拥有者。
3. 可读知识库列表、选库器、只读提示及成员管理界面。
4. 撤销后的历史脱敏、任务/SSE 停止输出、图片访问限制和对应测试。

两个阶段共用同一身份和权限入口，不另起权限框架。不单独发布“只有登录页面，业务 API 仍公开”的中间版本。

## 12. 验收与测试

新增建议测试文件：`test_auth.py`、`test_authorization.py`、`test_knowledge_isolation.py`、`test_asset_access.py`、`test_chat_migration.py`、`test_knowledge_migration.py`、`test_auth_view.cjs`、`test_knowledge_view.cjs`；同时更新现有工作流、任务、SSE、导航和导入测试。测试默认使用替身，不调用付费模型，不写真实聊天记录。

阶段划分：除 `UI-04`、`KB-03`、`KB-04` 为第二阶段外，其余场景均在第一阶段验收。`test_knowledge_view.cjs` 随第二阶段新增；第一阶段前端检查沿用文档页面测试。第二阶段重跑第一阶段回归，并增加共享授权测试。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AUTH-01 | 注册、大小写重名、并发重名、非法字段 | 仅创建一个普通用户及唯一默认私有库；无法提交角色提权；库内无明文密码 |
| AUTH-02 | 正确密码、错误密码、不存在和禁用账号 | 登录成功设置安全属性 Cookie；其他情况给出统一错误 |
| AUTH-03 | 过期、撤销、改密、禁用、服务重启 | 显式校验失效；改密/禁用令旧版本失效；Mongo 中有效登录可跨应用重启恢复 |
| AUTH-04 | 跨站请求、缺失 CSRF、过量请求 | 返回 403/429，无模型和存储业务副作用；上传也覆盖 |
| AUTH-05 | 数据库故障及认证限流器压力 | 503 可区分；不匿名放行；限流器内存有界 |
| ACL-01 | 用户 A 访问 B 的聊天、任务、SSE 和删除接口 | 统一 404，无内容泄露；管理员读取 B 的聊天同样失败 |
| ACL-02 | 客户端伪造 `user_id`、会话 ID、消息 ID | 不改变实际归属，不读取/更新他人消息，不创建越权任务 |
| ACL-03 | 历史传入模型、流式/非流式、澄清答案 | 模型只收到当前用户历史；助手消息每轮保存一次 |
| ACL-04 | 运行任务时退出、切换用户、修改密码 | 已接收任务继续归原用户；失效 SSE 在 5 秒内停止；非流式不向失效登录返回结果 |
| ACL-05 | 删除与问答同时提交、配额竞争、上传批次容量不足 | 无删除后复活记录；不突破配额；失败上传不预留部分可运行任务 |
| UI-01 | 登录页及普通用户业务页加载 | 登录页不发任务请求；普通用户可上传、看自己的任务；401 能解除模态锁并进入登录 |
| UI-02 | 两个标签页切换账号、页面返回缓存、旧请求迟到 | 清除旧账号内容，验证新身份，旧响应不能污染新页面 |
| UI-03 | A 导入时 B 查询或浏览 | 仅 A 自己的导入锁定；B 可排队，不能看 A 的任务和无权库活动 |
| UI-04 | 选库、新聊天、旧会话恢复及只读库 | 新聊天绑定库；切库不能复用旧历史；reader 无上传和分享操作 |
| KB-01 | A/B 上传同名文件和同名产品 | 两份数据、对象和产品索引并存，替换 A 文档不删除 B 的任何内容 |
| KB-02 | 产品匹配、稠密/稀疏、普通/HyDE、无产品条件 | 所有检索请求均包含已授权库过滤；无权库片段、型号和图片从未进入提示词 |
| KB-03 | A 授权 B 为 reader，C 无权限 | B 可查询并查看引用图片，不能上传/覆盖/授权/下载原文件；C 访问资源均失败 |
| KB-04 | 撤销 B 后读取历史、重放、取缓存、排队及运行中任务 | 当前授权重新验证；正文和标题脱敏/拒绝，SSE 在 5 秒内关闭，后续结果不发布 |
| KB-05 | 原文件、图片、伪造资产路径和旧匿名 URL | 按资产类型验证；MinIO 直链无匿名访问；跨库 URL 不通过图片白名单 |
| KB-06 | 同时上传、超容量、同批重名、失败及重试 | 配额原子预留和释放，不能跨用户覆盖；单批重名拒绝，失败不重复占位 |
| KB-07 | 管理员尝试访问非本人且未授权的库 | 不享有默认内容旁路，检索、文件、任务权限与普通用户相同 |
| MIG-01 | 旧记录、重复迁移、冲突、中断后恢复 | 默认隔离；迁移幂等；答案语义和引用关系保留，归属冲突不覆盖 |
| MIG-02 | 旧向量 schema、图片公开策略、无法映射引用 | 新集合带正确库字段；旧 URL 关闭；无法归属的内容隔离且不进入私有查询 |
| REG-01 | 原有上传、引用、导航、任务和 SSE 回归 | 原有有效行为保留，身份及接口变化对应更新预期 |
| SIM-01 | 第一阶段依赖和代码组织 | 新增运行依赖仅为密码哈希库；采用普通路由、`Depends`、PyMongo 和权限函数，无新增认证/权限框架或 JWT 双令牌机制 |
| SIM-02 | 第一阶段范围 | 普通用户可上传和查询本人库；成员路由不存在，手工成员记录不赋予访问权；管理员也不能跨用户访问 |

第一阶段真实联调使用普通用户 A、B 和管理员 C：A/B 分别上传同名但内容不同的文档，各自只能检索本人库，C 也无法访问；覆盖退出、改密、流式恢复、服务重启后文档清单恢复及原文件直链拒绝。直接核对数据库归属、向量查询范围和 HTTP 响应，不仅观察前端入口。

第二阶段增加共享场景：A 授权 B 只读后，B 显式切到 A 库才能检索 A 的内容，C 仍不可访问；撤销 B 后验证流式、历史、引用、图片和待执行任务失权。

- 配额预留在单进程任务锁内完成，启动时释放异常中断预留。正常完成后删除任务临时目录；存储长期故障导致的不可见孤立产物需要后续维护，未实现自动垃圾回收。
- 知识迁移采用人工确认 JSON 清单，复制并校验已有向量和对象；聊天只迁移可唯一映射的来源。迁移默认预览，实际应用需停服、备份并明确关闭旧桶匿名策略。实际环境尚未执行迁移。
- 本轮自动化及浏览器验证使用隔离替身；真实 MongoDB/Milvus/MinIO/MinerU/模型全链路仍需部署环境联调，不将模拟测试描述为生产验收。详见 `第一阶段实施记录.md` 与 `多用户运维与迁移.md`。
